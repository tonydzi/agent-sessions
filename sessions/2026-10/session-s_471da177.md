Основными кандидатами признаны облачные браузеры (Bright Data, Browser Use) и API-сервисы (CapSolver, Anti-Captcha/2Captcha и аналоги), а также условно-бесплатные решения (NopeCHA, Buster). Услуги различаются по стоимости (см. таблицу ниже), требованиям к данным (все требуют публичного ключа CAPTCHA и URL страницы, некоторые отправляют изображение/аудио на сервер) и ограничениям по использованию. # Расхождения и обсуждения  
- **Точность и скорость:** поставщики часто заявляют высокую надёжность и быструю реакцию (AntiCaptcha обещает 5 с, DeathByCaptcha – «мгновенное решение»), но независимые исследования скудны. Обзор [26] отмечает «маркетинговые» заявления об успехе без подтверждений. Независимые тесты 2025–2026 не публиковались, что вводит неопределённость.  
- **Человечество vs ИИ:** многие сервисы (2Captcha, AntiCaptcha, DeathByCaptcha) всё ещё задействуют людей для сложных задач (AntiCaptcha: «100% решено людьми»), тогда как новые (CapSolver, NopeCHA) полагаются на нейросети и OCR. Преимущества людей – более высокая точность на сложных вызовах, но больший риск утечки данных. ИИ-решения быстрее и дешевле, но могут ошибаться на разметках. Литература не даёт однозначного ответа; пользователи сообщают разные опыты в отзывах.  
- **Расширения и безопасность:** расширения типа Buster и AntiCaptcha требуют широкого доступа («доступ к данным для всех веб-сайтов»), что вызывает опасения безопасности. Браузерные расширения могут быть более уязвимы (обновления, цепочка поставок) по сравнению с серверами API. Этот фактор противоречит доверию, даже если расширения открыты (GPL).  

# Кандидаты и их компромиссы  
- **CapSolver (MCP-сервер)** – *Плюсы:* официальная интеграция для Claude/Codex через MCP; дешёвая стоимость (≈0.5–2 $/1000 для типовых CAPTCHA); поддержка Python/Selenium; ветви для обхода. *Минусы:* требуется регистрация и API-ключ, потенц. задержки сети. Нужны трафик (отправка URL+ключа) и возможен платёж вперёд.  
- **Browser Use** – *Плюсы:* полностью управляемый облачный браузер, решает CAPTCHA «из коробки»; интеграция через Python SDK; нет доплаты за распознавание CAPTCHA (входит в $0.02/час); тестируется реальными кейсами агентов. *Минусы:* нужно всегда онлайн-сессия в облаке (потенциально выше latency); передача всей страницы на сервер; плата за трафик ($5/GB). Бесплатный тариф недоступен (только после оплаты).  
- **Bright Data (MCP)** – *Плюсы:* проверенная платформа с бесплатным тарифом 5000 запросов/мес; интеграция через MCP для Claude («npx mcp-remote с токеном»); поддерживает разные CAPTCHA типы; платформа большого масштаба. *Минусы:* сложнее в настройке (требует Node/npm или npx); плата $1.50/1000 запросов после тарифа; передача контента страницы и возможные ограничения по объёму.  
- **Anti-Captcha/2Captcha** – *Плюсы:* простое API; низкий порог входа (API-ключ после регистрации); известный уровень цен (от $0.5–1 за 1000); есть расширения. *Минусы:* стоимость выше CapSolver; данные у «решателей» (люди); нет официального MCP, нужны обёртки.  
- **NopeCHA/Buster (расширения)** – *Плюсы:* бесплатны или почти бесплатны (NopeCHA – 100 реш./день бесплатно); интегрируются в браузер; минимальные настройки. *Минусы:* Buster решает только аудио reCAPTCHA, да и то медленно (автоматически, но распознаёт голос); NopeCHA – относительно новый (достоверность не подтверждена); расширения не интегрируются напрямую в консольные агенты, требуют ручных действий.  

# Возможные сбои (Failure Modes)  
- **Неверное решение CAPTCHA:** служба возвращает неправильный ответ (ошибочно решённый CAPTCHA), и сайт отклоняет форму. Обычно требуется повторить попытку (retry) или сменить провайдера. Для API-сервисов важно иметь логику повторной отправки (с учётом лимитов).  
- **Технические ошибки и задержки:** сеть может быть нестабильной, тайм-ауты API или высокие задержки. Например, антибот-платформы могут временно блокировать подозрительные запросы. Провайдеры указывают среднее время ответа ~5–10 с, но реальные метрики могут быть выше. Важно отслеживать p50/p95 задержек в тестах.  
- **Политики и лимиты:** если достигнут лимит или баланс исчерпан, API вернёт ошибку, и дальнейшие вызовы заблокируются. Некоторые сервисы (Bright Data) отключаются после исчерпания бесплатного лимита. Часто требуется ручное пополнение счёта.  
- **Безопасность и ответственность:** загрузка страницы в облако или передача через прокси может раскрыть конфиденциальные данные формы. В MSP-режиме (например, CapSolver) мы не передаём секреты, но любая информация на странице видна сервису. Всегда нужно проверять, что не отправляется чувствительное.

# План установки и настройки  
1. **Окружение:** создать изолированное Python-окружение (venv или conda). Установить версии библиотек, зафиксированные на дату окт.2026 (например, проверить текущие версии на PyPI или GitHub). Никогда не запускать `npx latest` без указания конкретного.  
2. **CapSolver:** установить SDK и MCP-сервер:
   ```bash
   pip install capsolver-core==<версия_на_сентябрь_2026>
   pip install capsolver-mcp==<версия_на_сентябрь_2026>
   ```  
   Добавить в конфиг агента (или файл `claude_desktop_config.json`):  
   ```json
   {
     "mcpServers": {
       "CapSolver": {
         "command": "capsolver-mcp",
         "env": { "CAPSOLVER_API_KEY": "ВАШ_КЛЮЧ" }
       }
     }
   }
   ```  
   Ключ (CAPSOLVER_API_KEY) хранить локально, не в коде. По окончании тестов удалить запись (для отключения – просто убрать этот раздел или закомментировать).  
3. **Bright Data MCP:** установить утилиту MCP (можно через npm/pnpm):
   ```bash
   npm install -g @brightdata/mcp@<версия_на_сентябрь_2026>
   ```  
   Получить API-token в учётной записи Bright Data. В конфиге Claude/Desktop добавить новый MCP-сервер:  
   ```json
   {
     "mcpServers": {
       "BrightData": {
         "command": "npx",
         "args": ["mcp-remote", "https://mcp.brightdata.com/mcp?token=ВАШ_TOKEN"]
       }
     }
   }
   ```  
   После эксперимента удалить или отключить этот сервер (удалить раздел из конфига).  
4. **Browser Use:** установить SDK:
   ```bash
   pip install browser-use-sdk==3.12.1
   ```  
   Задать API-ключ через переменную окружения `BROWSER_USE_API_KEY` (или указать в коде). Использовать через Python API, пример кода:  
   ```python
   from browser_use_sdk.v4 import BrowserUse
   with BrowserUse() as client:
       session = client.browsers.create()  # создаём новый браузер
       # убедиться, что session.live_url выдаёт ссылку на браузер
       # далее запустить CAPTCHA в session через Playwright
   ```  
   По завершении теста закрыть сессию. Для «отката» не требуются глобальные изменения, достаточно удалить SDK из окружения и сбросить переменные.  
5. **Тестирование:** начать с локальной тестовой страницы с демонстрационными sitekey (reCAPTCHA/hCaptcha из раздела тестовых ключей выше). Убедиться, что система получает ожидаемый dummy-токен. Далее постепенно переходить к публичным демо-формам провайдеров (с одним действием на разгадку за раз) с обязательным подтверждением вручную перед запуском каждого. Зафиксировать результаты: п50/п95 латентности, количество затрат ($), успешные и сбойные случаи на каждом уровне (распознавание, передача решения, верификация сайтом). Обязательно сравнить с ручным решением (бесплатным) на тех же тестах. Анализировать источники ошибок: неверно распознанные CAPTCHAs, проблемы загрузки страницы, нестабильность ответа API.
