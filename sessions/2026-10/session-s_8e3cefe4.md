## Как объяснить, что такое эвал

**Коротко, за 30 секунд:**
> "An eval is an automated exam for an AI system. You take a set of real examples with known good answers, run the model or agent on all of them, and score each output, either with plain code checks or with another LLM acting as a judge. Then every time you change a prompt, a model, or a tool, you re-run the exam and see in numbers whether you got better or broke something."

**Глубже, если попросят, минуты на две:**
1. **Зачем.** Один-два удачных ответа ничего не доказывают: LLM даёт разный результат на каждом запуске. Эвал превращает «вроде работает» в число, которое можно сравнить с прошлым запуском.
2. **Из чего состоит:**
   - **набор примеров (dataset)**: настоящие запросы, лучше всего взятые из живых трасс;
   - **сама система (model)**: промпт, модель или агент целиком;
   - **оценщики (scorers)**: простые проверки кодом (правильный ли JSON, есть ли цитата в источнике) и **LLM-судья** для того, что кодом не проверить (тон, полнота). В Weave всё устроено именно так: dataset + model + scorers, а прогоны сравниваются бок о бок.
3. **Ловушка, которую стоит назвать самому:** LLM-судья тоже ошибается. Его нужно сверить с оценками живого человека, иначе ты измеряешь мнение судьи, а не качество.
4. **Офлайн и онлайн.** Офлайн-эвал гоняют до релиза на фиксированном наборе. Мониторинг гоняют в продакшене на живом трафике. Связь между ними такая: упавшие живые трассы становятся новыми примерами в наборе.

**Твой пример из флота** (правдивый, не перебарщивай):
> "In my fleet I have a gate that checks every RAG citation against the source text. That's essentially a deterministic scorer. Each one started from a real failure: I write the failing test first, then the fix. That's the same loop Weave runs at scale: trace, find the failure, turn it into an eval case, prevent the regression."

⛔ Не говори «I use Weave». Говори «I built the same loop by hand».
